# ADR-002: AI 문제 캐싱 기능은 MVP 범위에서 제외한다

## 상태

Accepted

## 배경

AI 문제 생성 또는 검증 결과에 대한 캐싱 기능을 MVP에 포함할지 검토했다.

캐싱을 얇게 구현한다면 URL 기반으로 빠르게 처리할 수 있다. 동일 URL에 대해 이전 AI 응답을 재사용하는 방식이다.

하지만 URL 기반 캐싱은 다음 한계가 있다.

- 같은 URL이라도 원본 콘텐츠가 수정될 수 있다.
- 원본 수정 여부를 안정적으로 감지하기 어렵다.
- URL은 같지만 실제 내용이 달라진 경우 잘못된 캐시를 사용할 수 있다.

내용 기반 캐싱을 하려면 콘텐츠의 의미적 유사성을 판단해야 한다. 이를 위해서는 임베딩 기반 비교가 필요하다.

임베딩 기반 캐싱은 다음 구현 복잡도를 추가한다.

- 콘텐츠 추출 및 정규화
- 임베딩 생성
- 임베딩 저장소 구성
- 유사도 검색
- 캐시 적중 기준 설정
- 원본 변경 및 stale cache 처리

## 결정

AI 문제 캐싱 기능은 MVP 범위에서 제외한다.

MVP에서는 동일 입력에 대한 캐시 재사용보다 구현 단순성과 판단 정확성을 우선한다.

## 이유

- URL 기반 캐싱은 빠르게 구현할 수 있지만 원본 수정에 취약하다.
- 신뢰 가능한 캐싱을 위해서는 내용 기반 판단이 필요하다.
- 내용 기반 캐싱은 임베딩 기반 구현이 필요하다.
- 임베딩 저장소와 유사도 검색이 추가되면 MVP 구현 복잡도가 커진다.
- 현재 단계에서는 캐싱 최적화보다 핵심 AI 문제 생성 흐름 검증이 우선이다.

## 고려한 대안

### URL 기반 캐싱

URL을 키로 사용해 AI 응답을 캐싱하는 방식이다.

장점:

- 구현이 단순하다.
- 별도 임베딩 인프라가 필요 없다.
- 동일 URL 반복 요청에는 빠르게 대응할 수 있다.

단점:

- 원본 콘텐츠가 수정되어도 감지하기 어렵다.
- 오래된 결과를 재사용할 위험이 있다.
- URL은 같지만 내용이 다른 경우 정확성이 떨어진다.

### 내용 기반 캐싱

콘텐츠 내용을 임베딩하고 유사도 기반으로 캐시 적중 여부를 판단하는 방식이다.

장점:

- URL이 달라도 내용이 유사하면 캐시를 재사용할 수 있다.
- URL 기반보다 더 정확한 캐시 판단이 가능하다.

단점:

- 임베딩 생성 및 저장소가 필요하다.
- 유사도 검색 인프라가 필요하다.
- 캐시 적중 기준 보정이 필요하다.
- MVP 대비 구현 복잡도가 크다.

## 결과

MVP에서는 AI 문제 캐싱을 구현하지 않는다.

다음 상황이 발생하면 캐싱 도입을 재검토한다.

- 동일 URL 또는 동일 콘텐츠 요청이 반복적으로 발생하는 경우
- AI API 비용이 문제 되는 경우
- 응답 속도 개선이 MVP 이후 주요 요구사항이 되는 경우
- 임베딩 기반 인프라를 다른 기능에서 이미 도입한 경우

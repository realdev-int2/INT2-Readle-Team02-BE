# ADR-018: OAuth 인증 상태는 MySQL 기반 일회성 저장소로 관리한다

## 상태

Accepted

## 배경

OAuth callback의 `state`는 CSRF 방어와 callback 요청의 일회성 확인을 위해 필요하다. 애플리케이션이 새로고침되거나 여러 인스턴스로 배포되어도 동일하게 검증되어야 하며, 재사용된 callback은 차단해야 한다.

MVP에는 Redis를 운영하지 않고 서버 session 저장소도 두지 않는다. 따라서 OAuth 인증 상태를 서버 메모리나 특정 인스턴스에 묶지 않으면서, 한 번만 소비되었음을 보장할 저장소가 필요하다.

이 ADR은 ADR-007의 OAuth callback 보호 결정을 구체화하며, ADR-007을 대체하지 않는다.

## 범위

이 ADR은 OAuth authorization state의 저장, 조회, 일회성 소비 규칙만 다룬다.

OAuth provider 설정, callback endpoint, 토큰 발급, member 생성, 만료·소비 row의 물리적 삭제 방식은 이 ADR의 범위 밖이다.

## 결정

OAuth authorization state는 MySQL 기반 일회성 저장소로 관리한다. 서버 session, Redis, 인메모리 상태, signed/stateless state는 사용하지 않는다.

OAuth 시작 시 다음 값만 저장한다.

- `state`의 hash
- provider
- `OAUTH_ALLOWED_RETURN_PATHS`의 Spring-style allowlist pattern과 매칭한 상대 path와 선택적 query의 `returnTo`(예: `/`, `/dashboard`, `/quizzes/**`; `/**` 단독 전체 허용은 금지)
- application-encrypted PKCE `code_verifier`
- 10분 후 만료 시각
- 생성 시각과 사용 시각

원문 `state`는 저장하지 않는다. 브라우저는 원문 `state`를 짧은 수명의 HttpOnly cookie로만 보관한다.

`returnTo`는 외부 URL을 허용하지 않는다. query를 제외한 path만 allowlist와 매칭하며, 없는 값과 scheme·authority·host·fragment, `//`, backslash, CR/LF, 인코딩 우회가 있는 값은 path를 `/`로 정규화하고 허용된 query는 보존한다.

Callback은 cookie의 원문 `state`와 요청의 `state`가 일치하는지 확인한 뒤, state hash와 provider로 row를 찾는다. `used_at IS NULL` 및 미만료 조건을 포함한 원자적 consume으로 한 번만 사용할 수 있게 한다.

state 불일치, 만료, provider 불일치, 재사용 또는 저장소 사용 불가는 모두 fail-closed로 처리한다. 이 경우 OAuth token 또는 member를 생성하지 않는다.

만료되었거나 소비된 row의 물리적 삭제는 운영 후속 작업이다. authorization state의 유효성은 삭제 여부가 아니라 만료 시각과 `used_at` 규칙으로 판단한다.

## 고려한 대안

### 서버 session

OAuth state 관리에는 사용할 수 있지만 별도 session 저장소 또는 인스턴스 고정이 필요해 무상태 애플리케이션 배포와 맞지 않는다.

### Redis

TTL과 일회성 소비 구현에는 적합하지만, MVP에 없는 운영 컴포넌트와 장애 지점을 추가한다.

### Signed/stateless state

서버 저장소 없이 검증할 수 있지만, 한 번 사용된 state의 재사용을 서버가 신뢰성 있게 차단하기 어렵다.

### 인메모리 저장소

구현은 단순하지만 새로고침, 재시작, 다중 인스턴스 환경에서 state를 일관되게 검증할 수 없다.

## 결과

OAuth authorization state는 기존 MySQL에서 관리되어 Redis나 session store가 필요 없다. 애플리케이션 인스턴스와 무관하게 동작하며, 조건부 update 또는 동등한 잠금으로 재사용을 한 번만 차단한다.

MySQL read/write와 동시성 제어가 필요하며, MySQL의 일회성 consume 동시성 테스트를 추가하거나 유지한다. 만료 시각과 `used_at` 조건이 authorization state 유효성의 단일 기준이다.

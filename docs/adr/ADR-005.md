# ADR-005: 학습 이력 기반 개인화는 MVP 범위에서 제외한다

## 상태

Accepted

## 배경

팀 내에서 다음과 같은 제안이 있었다.

- 이미 맞힌 개념은 출제 빈도를 낮춘다.
- 자주 틀리는 태그(예: Spring Transaction, JVM)는 반복 출제한다.
- 같은 주제의 새 아티클 입력 시, 이전에 학습한 개념과 연결해 문제를 생성한다.
- "이번 아티클은 이전에 학습한 JPA 영속성 컨텍스트와 연결됩니다" 같은 피드백을 제공한다.

이 제안이 실현되면 서비스가 단발성 AI 호출을 넘어 사용자별 학습 컨텍스트를 기억하고 누적하는 AI로 발전할 수 있어, 경쟁 서비스 대비 핵심 차별점이 될 수 있다는 점에는 팀 내 공감대가 있었다.

다만 이를 구현하려면 다음이 선행되어야 한다.

- 태그·개념 단위의 정답 이력 설계 (사용자별로 어떤 개념을 맞혔는지/틀렸는지 구조화된 데이터로 축적)
- 아티클 간 의미적 유사도 판단 (임베딩 기반 검색 등)

이는 사실상 RAG(Retrieval-Augmented Generation)에 가까운 아키텍처를 요구하며, 4주라는 MVP 개발 기간 안에서 다음 문제를 일으킬 수 있다.

- 정답 이력 데이터 모델과 임베딩 검색 인프라를 새로 설계·구축해야 해 개발 범위가 크게 늘어난다.
- 검증되지 않은 유사도 판단 로직이 오히려 부적절한 문제 연결이나 추천을 유발할 수 있다.
- MVP의 핵심 목표인 "북마크만 하고 읽지 않는 문제(bookmark syndrome) 해결"과 직접적인 관련성이 낮다.
- 개인화 로직 검증에 시간이 소요되어 핵심 기능(퀴즈 생성, AI Validation Service 등)의 완성도가 떨어질 위험이 있다.

## 결정

학습 이력 기반 개인화 문제 추천 기능은 MVP 범위에서 제외한다.

해당 기능은 Future Roadmap으로 이관하며, MVP 종료 후 별도 검증을 거쳐 도입 여부를 재검토한다.

## 이유

- 차별화 효과는 인정하지만, 검증되지 않은 상태로 도입하면 오히려 문제 추천의 신뢰도를 떨어뜨릴 위험이 크다.
- 개인화 문제 추천은 태그별 정답 이력 설계와 임베딩 기반 유사도 판단이 필요해 RAG에 가까운 아키텍처를 요구하며, 4주 내 구현이 현실적으로 어렵다.
- MVP는 아티클 기반 퀴즈 자동 생성과 학습 현황 대시보드를 통한 학습 현황 파악이라는 핵심 가치 검증에 집중해야 한다.
- MVP 단계에서는 개인화 최적화보다 안정적인 핵심 기능 제공이 우선이다.

## 결과

MVP에서는 학습 이력 기반 개인화 문제 추천을 제공하지 않는다.

대신 오답 태그는 단순 기록 수준으로만 남기고(예: 학습 현황 상 표시), 개인화 추천·반복 학습 알고리즘·난이도 자동 조절은 Out of Scope로 명시한다.

다음 상황이 확인되면 개인화 기능 도입을 재검토한다.

- MVP 운영을 통해 태그·개념 단위 정답 이력 데이터가 충분히 축적된 경우
- 아티클 간 유사도 판단을 위한 임베딩 검색 아키텍처가 별도로 설계·검증된 경우
- 사용자 피드백에서 반복 학습·개인화 추천에 대한 요구가 확인된 경우
- 핵심 기능(퀴즈 생성, 학습 현황 대시보드)이 안정화되어 추가 리소스를 개인화 기능에 투입할 여력이 생긴 경우

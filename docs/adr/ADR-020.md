# ADR-020: 퀴즈 풀이 중 새로고침 시 답안 유실은 서버 저장 없이 브라우저 sessionStorage로 방지한다

## 상태

Accepted

## 배경

퀴즈 풀이 화면을 설계하는 과정에서, 서버가 문항별 진행 상태(`current_question_no`)와 풀이 중 답안(`quiz_answer`)을 실시간으로 갱신할지 여부를 논의했다.

이전/다음 문항 이동 시 이미 입력한 답안을 유지하는 기능 자체는 프론트엔드 상태만으로 구현 가능하다는 데 팀 합의가 있었고, 서버가 이 값을 실시간으로 관리해야 하는 경우는 다음과 같은 시나리오로 정리되었다.

- 새로고침 후 작성 중인 답안 복구
- 다른 기기/브라우저에서 이어풀기
- 풀이 도중 이탈 후 나중에 재개
- 서버 기준 문항별 진행률 영속 관리

위 시나리오들은 MVP 범위를 확대하는 기능으로 판단되어, `current_question_no`와 풀이 중 `quiz_answer` 업데이트는 MVP에서 제외하고 Future 작업으로 미루기로 결정했다. 이에 따라 DB 스키마에서 `current_question_no` 컬럼도 제거하기로 했다.

MVP 접근 방식은 다음과 같이 정리되었다.

- `quiz_attempt`는 풀이 시작 시 생성하여 `started_at`, `status = IN_PROGRESS` 기록
- 풀이 중 답안과 현재 문항 번호는 프론트엔드 상태로만 관리
- 최종 제출 시 한 번에 모든 답안을 서버로 전송 → `quiz_answer`, `quiz_result` 생성
- 제출 완료 후 `quiz_attempt.status = SUBMITTED`, `submitted_at` 기록

이 결정 이후, 프론트엔드 개발 중 실제로 풀이 화면에서 새로고침(F5) 시 작성 중이던 답안이 전부 사라지는 문제가 확인되었다. 서버 중간 저장 기능은 MVP 범위에서 이미 제외하기로 했지만, 같은 브라우저 세션 내에서의 새로고침 정도는 서버 API 추가 없이도 프론트엔드만으로 방지할 수 있다는 판단 하에 대응 방안을 마련했다.

## 결정

퀴즈 풀이 중 답안 유실 문제는 **서버 저장이 아닌 브라우저의 `sessionStorage`를 이용한 클라이언트 측 임시 저장(Draft)**으로 해결한다.

- 사용자가 문항의 답안을 선택/입력할 때마다 현재 풀이 상태를 `sessionStorage`에 저장
- 새로고침 또는 브라우저 뒤로 가기/앞으로 가기 시, 저장된 데이터를 검증 후 복원
- 저장 시 직렬화 비용을 고려해 일정 시간(예: 400ms) 디바운스 적용
- 저장된 데이터의 손상 여부(버전 불일치, null 등)를 런타임에 확인하는 스키마 유효성 검증 적용
- SSR 환경 및 스토리지 접근이 차단된 브라우저(샌드박스 등)에서도 화면 렌더링이 멈추지 않도록 `try-catch` 및 방어 로직 적용
- 퀴즈를 최종 제출하여 결과 대기 화면으로 넘어갈 때, 해당 퀴즈의 임시 데이터를 `sessionStorage`에서 정리(Clear)

서버의 `quiz_attempt`/`quiz_answer` 스키마나 API에는 변경이 없으며, 어디까지나 클라이언트 로컬 상태 보호 목적의 보완이다.

## 이유

- **기존 결정과의 정합성**: "이전/다음 문항 이동은 프론트엔드 상태만으로 처리 가능하다"는 이전 합의의 연장선으로, 서버 API나 스키마 변경 없이 대응할 수 있다. `current_question_no` 제거 결정을 번복할 필요가 없다.
- **실제 사용자 경험 문제 해소**: 서버 중간 저장을 포기한 것과 "새로고침 한 번에 모든 답안이 날아가는 것"은 다른 문제다. 후자는 사용자가 실수로 F5를 누르거나 브라우저가 갱신되는 흔한 상황에서 발생하는 UX 결함이라, MVP 범위 밖으로 미루기엔 리스크가 크다고 판단했다.
- **비용 대비 효과**: `sessionStorage` 기반 임시 저장은 서버 API, DB 스키마 변경이 전혀 없고, 프론트엔드 단독으로 구현 가능해 MVP 일정에 미치는 영향이 적다.
- **범위의 명확한 한계**: `sessionStorage`는 탭/세션이 완전히 종료되면 사라지고 다른 기기·브라우저와 공유되지 않으므로, "다른 기기에서 이어풀기"나 "이탈 후 나중에 재개"까지 해결하지는 않는다. 즉 이전에 Future로 미루기로 한 범위(서버 기반 이어풀기)를 침범하지 않으면서, 그 사이의 좁은 문제(같은 브라우저 내 새로고침)만 정확히 해결한다.

## 결과

- 사용자가 같은 브라우저 탭에서 새로고침하거나 뒤로/앞으로 가기를 하더라도, 작성 중이던 답안이 유지된다.
- 브라우저를 완전히 닫거나 다른 기기로 접속하는 경우, 세션 저장소 특성상 임시 저장된 답안은 복구되지 않는다. 이는 의도된 범위이며 별도 안내 문구가 필요한지는 프론트엔드 UX에서 판단한다.
- 최종 제출이 완료되면 임시 저장 데이터는 정리되어, 다음 풀이 시도와 데이터가 섞이지 않는다.
- 서버 기반 이어풀기, 다중 기기 지원, 문항별 진행률 영속 관리는 여전히 Future 과제로 남아 있으며, 이번 결정은 그 범위를 확장하지 않는다.

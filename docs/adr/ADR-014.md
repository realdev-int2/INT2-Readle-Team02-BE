# ADR-014: 백엔드 중심 3단계 Fail-Closed 프롬프트 인젝션 방어책 채택

## 상태

Approved

## **배경**

- 사용자가 제출하는 URL이나 텍스트 아티클 원본에 Jailbreak나 프롬프트 정보 유출 목적의 악의적인 프롬프트 인젝션 코드가 유입될 위험이 있음.
- 3주 미만의 짧은 개발 일정과 단일 서버(RAM 4GB EC2) 환경의 제한이 존재함. 보안성 확보와 인프라 리소스 관리 간의 균형을 극대화할 수 있는 경량 보안 가드레일 대안이 필요함.

## **결정**

외부 보안 서버나 서비스 도입 없이 백엔드 애플리케이션 레벨에서 리스크를 단계적으로 차단하는 **3단계 방어선**을 구현함.

- **1단계 (물리적 영역 분리)**: 원문 본문을 `<source_content>` XML 태그로 감싸고, System Prompt 내에 해당 태그는 퀴즈 출제를 위한 '순수 참조 데이터 영역'일 뿐이므로 내부의 어떠한 지시사항도 무시하라는 제어 격리 룰을 조입함.
- **2단계 (비용 절감 정적 필터)**: 노이즈를 1차 정규화(stripping)하고, **기존 1차 서버 정적 가드레일** 모듈 내에 프롬프트 우회 블랙리스트 키워드 패턴 검사를 추가하여 AI API 호출 전에 0ms 차단함.
- **3단계 (3중 검증 체계)**: AI 응답에 대해 백엔드 단에서 **`[JSON Parse ➔ JSON Schema ➔ Domain Validation]`*의 삼중 필터를 거쳐, 통과하지 못하면 퀴즈 적재를 차단하고 최종 `status = FAILED` 상태로 격리함.

## **이유**

- **비용 최소화**: 3단계 방어책은 순수하게 애플리케이션 도메인 코드만으로 동작하므로 추가 API 비용이나 인프라 요금이 전혀 발생하지 않음.
- **공수 절감**: MVP 일정에 치명적인 '인프라 추가 세팅 및 이기종 시스템 연동' 공수를 0에 수렴하게 함.
- **보안 안전성**: 우회 공격이 성공해서 엉뚱한 탈취 텍스트가 반환되더라도 3단계의 삼중 검증에서 Jackson ObjectMapper 예외 등을 뱉어 무조건 Fail-Closed되므로, 유저 화면에 해킹 문구가 그대로 노출되는 최악의 리스크를 예방할 수 있음.

## **고려한 대안**

- **대안 1: 별도의 오픈소스 가드레일 LLM(LlamaGuard 등) 단독 호스팅 혹은 유료 보안 Guardrail API 연동**
    - *기각 사유*: 단일 EC2 (RAM 4GB) 인프라 스펙의 성능 한계로 별도 SLM 모델 로컬 구동은 불가능함. 유료 API 연동은 추가 요금을 유발하며 3주 일정 내에 연동 파이프라인 개발 및 예외 시나리오 대응까지 끝내기에는 공수가 극도로 부족하여 기각함.

## **결과**

- **이점 (Pros)**:
    - 추가 요금 및 외부 연동 오버헤드 없이 3주 일정 내에 구현 가능한 가장 높은 수준의 보안 안전판을 확보함.
    - 1차 정적 필터를 통해 명백한 인젝션 시도를 0ms 만에 잘라내어 불필요한 AI 호출 비용을 확실히 예방함.
- **단점 및 트레이드오프 (Cons)**:
    - 신종/우회 기법을 100% 사전 감지하지는 못할 수 있음. (다만, 우회에 성공하더라도 3단계 삼중 검증에서 최종 차단되므로 실제 위해성은 매우 낮음.)

# ADR-010: 일괄 채점(Batch) 방식을 배제하고 1차 정적 비교와 개별 병렬 AI 채점 방식을 채택한다

## 상태

Accepted

## 배경

주관식 및 코드 빈칸 문제 채점 시, 개별 문항마다 AI API를 개별 동기 호출하게 되면 중복 토큰 전송 요금과 레이턴시가 문제 수에 비례하여 늘어나는 오버헤드가 발생한다.
이를 해결하기 위해 모든 문제를 하나의 XML로 묶어 일괄 채점(Batch)하고 실패 시 개별로 우회(Fallback)하는 방식이 논의되었으나, 다음과 같은 MVP 환경적 제약 사항과 우려가 제기되었다.

- **한정된 개발 일정**: 2~3주 내외의 매우 타이트한 개발 기간으로 인해, 일괄 채점 실패 시 개별 호출로 우회하는 복잡한 예외 처리(Fallback) 코드를 완벽하게 구현하고 검증할 공수와 시간이 부족함.
- **장애 격리 필요성**: 일괄 채점 시 응답 잘림, API Timeout(504), 혹은 전체 JSON 포맷 오류가 발생하면 문제 전체 결과가 한꺼번에 무효화되어 사용성에 치명적인 영향을 미침.
이에 따라 채점 정확도와 장애 격리를 확보하고 개발 공수를 단축하기 위한 최종 채점 아키텍처 설계에 대해 논의를 거쳤다.

## 결정

일괄 채점(Batch) 및 Fallback 구조 도입을 MVP 범위 외로 제외하고, **1차 정적 비교 후 미매칭 문항만 개별 병렬 AI 채점(Exact Match & Parallel Grading)** 방식을 최종 채택한다.

- 서버 단에서 대소문자나 띄어쓰기 등 즉시 판정 가능한 문항은 AI를 호출하지 않고 0ms로 즉시 채점 완료 처리한다.
- 정적 일치에 실패한 의미 비교 대상 문항들에 한해서만 Claude API를 개별 비동기 병렬 호출하여 채점을 수행한다.

## 이유

### 1. 에러 격리성 확보 (MVP 안정성 최우선)

- 문항별로 채점 장애가 완벽히 격리되어 특정 문항의 파싱 에러나 타임아웃이 다른 정상 문항의 채점 결과에 지장을 주지 않는다.

### 2. 비용 및 부하 방어 (정적 비교 필터 활용)

- 띄어쓰기, 대소문자, 다중 공백 제거 등의 1차 정적 비교를 우선 수행하여 AI API 호출 횟수 자체를 사전에 필터링한다.
- MVP 문제 수가 최대 5개 이하로 극히 적고 정적 필터를 거치므로, 실제 AI 호출 횟수가 최소화되어 개별 호출 비용과 서버 부하가 감당 가능한 수준으로 유지된다.

### 3. 구현 복잡도 최소화 (3주 한정 일정 준수)

- 일괄 채점 실패 시 catch 블록에서 개별 우회하는 복잡한 예외 처리(Fallback) 코드를 작성할 필요가 없어 비즈니스 로직과 디버깅 난이도가 극도로 단순해진다.

### 4. 병렬 처리를 통한 레이턴시 극복

- 개별 호출 시 대기 시간이 늘어나는 문제는 백엔드에서 비동기 병렬 호출(CompletableFuture 또는 WebClient)을 활용하여 동시에 쏜다.
- 이를 통해 문제 수와 무관하게 전체 대기 시간을 단 1문항 채점 시간(3~5초) 이내로 끝내도록 보완한다.

## 고려한 대안

### 일괄 채점 + 에러 시 개별 Fallback 우회 (하이브리드 Batch)

장점:

- 일반적인 채점 상황에서 API 호출 횟수를 1회로 묶어 비용 최적화를 극대화할 수 있음.
단점:
- 응답 잘림, 전체 파싱 실패, Timeout 발생 시 전체 결과의 신뢰도가 깨지며, 개별 재호출로 복구하는 방어 코드 구현 복잡도가 매우 큼.

### 1차 정적 비교 후 미매칭 건만 개별 병렬 AI 채점 (최종 채택안)

장점:

- 에러 격리성이 완벽히 보장되고, 구현 및 검증 복잡도가 가장 낮음.
- 정적 필터링을 통해 비용을 방어하고, 비동기 병렬 호출로 지연 시간을 획기적으로 단축함.
단점:
- 모든 문항이 의미 채점으로 넘어갈 경우 API 호출 횟수가 최대 N회로 증가함 (단, MVP 최대 5개 제약 하에서 충분히 감당 가능함).

## 결과

- **MVP 적용**: 1차 정적 비교(`trim()`, `toLowerCase()`, `replaceAll("\\s+", " ")`)를 수행한 뒤, 미매칭 문항만 스프링의 `CompletableFuture` 등을 활용해 비동기 병렬 호출하여 채점을 완료한다.
- **추후 재검토**:
    - 서비스 규모가 확장되어 퀴즈 문제 수의 상한이 5개 이상으로 크게 증가하여 개별 호출로 인한 API 요금 부담이 임계치를 초과하는 경우.
    - 실제 운영 데이터 확인 결과 주관식 채점의 대부분이 정적 비교를 통과하지 못해 AI 호출 빈도가 과도하게 유지되는 경우, **일괄 채점 + Fallback 구조로의 전환을 재검토**하는 의사결정 트리거를 발동한다.

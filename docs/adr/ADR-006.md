# ADR-006: Next.js BFF 도입을 배제하고 React와 Spring Boot 구조를 채택한다

## **상태**

Accepted

## **배경**

사용자 콘텐츠 입력, 크롤링, AI 검증 등의 작업을 효율적으로 처리하기 위해 프론트엔드 전용 서버인 Next.js BFF(Backend For Frontend) 아키텍처를 도입할지 논의했다.

- BFF 도입 찬성
    - 크롤링과 같은 I/O 작업에서 자바스크립트 기반의 빠른 성능을 얻을 수 있다
    - AI 응답 대기 등의 비동기 처리를 Next.js 백라운드에서 처리하여 Spring 코어 백엔드의 상태 관리 및 메시지 큐(MQ) 도입 부담을 낮출 수 있다.
    - 백엔드 서버 진입 전 1차 검증이 가능하고 SEO나 성능 면에서도 SSR/SSG 지원의 장점이 있다.
- BFF 도입 반대
    - 대량 동시 크롤링이 아닌 단발성 URL 요청 구조이므로 Jsoup과 Node.js 간의 실질적인 크롤링 성능 차이가 크지 않다.
    - Next.js에서 AI API를 호출하고 결과를 Spring 서버 DB에 저장하는 과정에서 부분 실패 케이스에 대한 예외 처리 및 재시도 전략이 복잡해진다.
    - BFF 레이어가 추가되면서 발생하는 추가 레이턴시와 두 서버 간의 보안/인증 처리가 개발 범위를 늘릴 수 있다.

## **결정**

Next.js BFF 도입을 반려하고, MVP 단계에서는 React 프론트엔드와 Spring Boot 백엔드 아키텍처를 채택한다.

비동기 판정 처리 및 크롤링 상태 관리 등은 Spring Boot 백엔드 내부에서 비동기 처리 기법을 활용하여 해결한다.

## **이유**

BFF 도입 시 AI 호출과 데이터베이스 저장 로직이 여러 레이어에 산재하게 되어 코드 복잡도가 전이되고 유지보수가 어려워질 수 있다.

AI 응답 성공 후 Spring DB 저장 과정에서 발생하는 부분 실패 케이스에 대한 트랜잭션 관리와 복잡한 재처리 예외 로직을 설계해야 하는 비용이 추가된다.

네트워크 레이어가 하나 더 추가됨에 따라 추가적인 레이턴시가 발생하여 MVP에서 목표로 하는 p95 5초 타임아웃 조건을 맞추는 데 불리할 수 있다.

동시 대량 크롤링이 일어나지 않는 MVP 스펙상 Jsoup 라이브러리를 활용한 정적 크롤링만으로도 충분한 성능을 낼 수 있다.

Spring Boot 내부의 비동기 기능 등을 활용하면 별도의 복잡한 인프라(BFF 및 메시지 큐) 구성 없이도 비동기 적합성 검증 요구사항을 충분히 충족할 수 있다.

## **고려한 대안**

### **Next.js BFF 도입**

Next.js를 프론트엔드 전용 백엔드로 배치하여 크롤링, AI 호출, 가드레일 검증을 전담하게 하고 코어 백엔드에는 완성된 데이터만 전달하는 방식이다.

장점:

- 크롤링 등 I/O 비동기 작업 효율이 좋다.
- 코어 백엔드(Spring)가 AI 응답 대기 등의 비동기 상태를 직접 관리할 필요가 없어 비즈니스 로직이 단순해진다.
- 서버 진입 전 1차 입력 검증이 용이하다.

단점:

- 전체 시스템 레이어가 늘어나 운영 복잡도와 네트워크 레이턴시가 증가한다.
- 두 서버 간의 데이터 동기화 및 부분 실패 처리를 위한 공수가 추가된다.
- 코어 로직이 분산되어 장기적으로 유지보수가 어려워질 수 있다.

### **React와 Spring Boot 단일 백엔드 구성**

일반적인 React 클라이언트와 Spring Boot 코어 백엔드 간의 직접 통신 구조를 유지하는 방식이다.

장점:

- 네트워크 레이어가 단순하여 레이턴시 관리에 유리하다.
- DB 데이터 정합성 보장 및 예외 처리가 하나의 백엔드 트랜잭션 범위 내에서 이루어져 단순하다.
- 팀 내에 익숙한 아키텍처로 빠른 MVP 개발이 가능하다.

단점:

- AI 비동기 판정 대기 상태 관리 및 크롤링 작업을 Spring 백엔드 내에서 동시 처리해야 하므로 백엔드 내부 설계가 복잡해질 수 있다.

## **결과**

MVP 단계에서는 React와 Spring Boot 단일 백엔드 결합 아키텍처를 공식 채택하고 Next.js BFF 서버는 구성하지 않는다.

비동기 검증 상태 관리는 Spring Boot 백엔드에서 구현하며, 크롤링은 Spring Boot 서버에서 Jsoup 라이브러리를 사용하여 처리한다.
